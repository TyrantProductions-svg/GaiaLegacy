## Ownership and admission

Gate C clarification: only explicitly owned direct GAIA_ASSET_WORKSPACE membership
in an isolated temporary scene is exported. Nested/linked/shared ownership rejects.
No `.blend` save, global preferences, add-on/dependency, viewer or runtime change.
The official exporter uses audited explicit settings; its PENDING receipt is not
HAND_TOOL_V0 validation. Exact GLB bytes pass through the existing Gate B CLI in a
separate headless process. Gate C does not change any semantic profile rule.
See the Gate C plan/notes and `docs/model-authoring-provenance.md` for evidence.

Gate B six-finding closure is now controller-authorized. The normative contract
adds PNG_V0/JPEG_V0: bounded container preflight before JDK decode, no arbitrary
metadata/color transforms, metadata-neutral memory input, canonical RGBA8 sRGB,
and once-per-images[i] accounting. Both chunk/marker limits are 256. No decoder
dependency, profile widening, Gate A restart, viewer or runtime integration.

Use the existing `tools` module, but NOT its main implementation classpath:
that classpath currently includes both `engine` and `game`. An independent
`modelInspector` source set owns offline admission/validation and a separate
`modelInspectorTest` suite runs headlessly. It must not inherit engine, game,
LWJGL, native libraries, or the production UI. Java 17 remains the API/bytecode
target; JDK 21 is the current repository build environment.

Architecture A is a Java CLI/core first, with an optional separate-process viewer
later. Alternatives were an embedded game preview (unnecessary runtime coupling)
and a browser viewer (another technology/runtime and delivery surface). The
approved choice minimizes runtime coupling, not necessarily future viewer code.

JglTF 3.0.1 is a tools-only candidate admitted through executable tests and exact
dependency/license receipts. Do not import JglTF's viewer, renderer, extensions,
or model-builder modules. JglTF is NOT a security boundary.

```text
explicit local GLB input stream
  -> bounded immutable byte snapshot
  -> strict GLB/container + streaming JSON security preflight
  -> reject all URI fields and all nonempty extension declarations/objects
  -> strict Jackson binding to public JglTF v2 DTOs -> GltfAssetV2
  -> Gate A: admission receipt only, NOT asset approval
  -> Gate B: semantic validator and bounded immutable inspection document
  -> Gate D: optional read-only viewer, after its own approval
```

Preflight runs to completion before any JglTF invocation. Duplicate JSON keys,
encoding ambiguity, oversized/nested input, unknown container chunks, URI and
extension escape routes fail closed. The verified byte snapshot is the same
snapshot decoded; no second filesystem read (TOCTOU). Parser/decode rejections
are typed, bounded, and do not echo untrusted JSON, paths or URI values. Caller
stream I/O failures remain `IOException`; a future CLI must sanitize those before
display rather than assuming arbitrary source I/O messages are safe.

Admission-test correction: JglTF 3.0.1's `GltfAssetReader` can log/swallow property
mapping errors despite `setJsonErrorConsumer`. Its constructor registers a mapper
module with the logging consumer; later configure does not replace that module.
The tested production adapter therefore uses a strict Jackson mapper with public
v2 DTOs and `GltfAssetV2`, NOT that tolerant reader, private JglTF utilities,
reflection, global logger interception or a patched dependency. The known-good
triangle test still exercises the upstream reader/model API for compatibility.

Gate A maps JSON to JglTF's asset representation only. It does NOT create a
general untrusted `GltfModel`, expand accessors, decode textures, validate node
graphs, claim geometric correctness, or expose an asset as runtime-ready.

Gate E controller contract closure freezes strict rejection of `null` elements in
glTF core numeric/integer/index arrays before lossy DTO mapping. This does not
change optional whole-property nulls or bounded arbitrary `extras` JSON. The same
closure adds HAND_TOOL_V0 hard declaration bounds of 8 textures and 8 samplers;
all root declarations count and resource-limit rejection precedes snapshot
projection. Material/image limits remain 8/4.
Gate B must add semantic/resource checks before those expansion operations.
A trusted tiny triangle fixture may exercise `GltfModels.create` in an admission
test to establish library compatibility, not as an untrusted production path.

## Revised coordinate, root and authoring decisions

- Standard glTF right-handed coordinates, meters, Y-up. This does NOT assign
  +Y, -Z, or any other axis as every hand tool's working direction.
- Exactly one logical root named `GAIA_ASSET_ROOT`; an accidentally solitary
  top-level node is insufficient. Gate B validates scene/root/hierarchy.
- Pivot location, local working axis, grip/attachment frame and intended scale
  are asset-local authoring/sidecar semantics. No runtime hand convention has
  been frozen. A later HAND_TOOL default requires actual runtime evidence.
- `.blend` sources stay in user-controlled local authoring/staging storage.
  Phase 17.75 does NOT admit them as tracked production repository files or
  choose an LFS policy. A receipt may identify source SHA-256 and exporter
  versions; Git object IDs are not file integrity hashes.
- Blender/MCP are offline authoring tools only. No scene change, save, export,
  connectivity spike, or addon setup is needed in Gate A. Later authorized work
  is restricted to `GAIA_ASSET_WORKSPACE`; saving/overwriting `.blend` still
  needs explicit approval.

## Profile and future data flow

The initial profile is **GAIA_GLB_HAND_TOOL_V0**, for a hand tool/simple prop,
not a universal limit for all future Gaia asset classes. See
[the contract](../../architecture/gaia-glb-hand-tool-v0.md) for normative limits
and which checks belong to which gate.

```text
user-approved local .blend
 -> explicit temporary GLB export (not game resources)
 -> bounded preflight -> headless semantic validation
 -> read-only viewer -> human approval
 -> later separately authorized asset admission + receipt
```

No second item/material/asset registry. glTF material descriptions are document
data, not Gaia material registrations. `gaia:chisel`, `DETAIL_PRECISION`, integer
ItemStack identity, ATLAS_REGION presentation and current gameplay remain
unchanged. Runtime 3D presentation is not implemented by this phase's admission
gate. Phase 17.5 typography/theme is reused only if an actual project UI surface
is later selected, not pulled into a headless development tool.

## Gates and acceptance

### Gate 17.75B controller contract clarification

The frozen HAND_TOOL_V0 contract now defines independent unique and scene-expanded
geometry accounting. Unique counts cover every declared primitive, including
unreachable payload, and count shared POSITION accessors once per primitive.
Expanded counts cover every reachable default-scene node-to-mesh instance without
duplicating geometry arrays. Each domain independently caps triangles at 10,000
and vertices at 30,000 and warns above 4,000 triangles. Checked arithmetic applies
before allocation; unreachable payload remains independently invalid.

Only proper rigid transforms are supported: finite translation and rotation, unit
scale, orthonormal affine matrix basis and determinant +1. One absolute tolerance,
`RIGID_TRANSFORM_EPSILON = 1e-4`, applies as specified in the contract; no source
normalization or rewriting is permitted. No fixed working axis, sidecar, identity
translation/rotation or Blender proof is added. This resolves the two opening
ambiguities by controller decision, not by weakening Gate A.

   pinned licensed dependency, minimal bounded preflight, tiny owned fixtures,
   Java compatibility evidence, no GL initialization. STOP for review.

   decompression budgets, deterministic bounded diagnostics. No viewer. STOP.
3. **17.75C — Authoring/export trial (controller-approved):** explicitly authorized

## Gate 17.75D controller-approved viewer design

The viewer is a separate tools-only JVM/window, not Gaia runtime GLB support.
`modelViewer` and `modelViewerTest` do not inherit `tools.main`. They consume the
existing `modelInspector` output and dependencies plus `engine`'s generic Window,
MainThreadGuard and ShaderProgram infrastructure. No engine or game source change,
new dependency/UI framework, runtime SVG/font pipeline, Blender operation or game
session is needed. Engine's existing transitive native libraries remain engine
infrastructure, not new inspector dependency versions. The headless inspector
continues to have no graphics dependency.

One explicit local GLB enters `GaiaGlbValidator.validate(InputStream)` before the
window is created. FAIL has no displayed model. Only the resulting immutable
`ValidatedModelSnapshot` enters the viewer's CPU projection and GPU upload; no
JglTF DTO/accessor, original JSON, or encoded image container reaches rendering.
CPU packing checks GPU representability without reinterpreting profile legality.
An unrepresentable candidate fails presentation without changing validation or
the current model. No asset transform, pivot, scale or center is rewritten.

The diagnostic renderer uses OpenGL 4.1 / GLSL 410, POSITION/NORMAL/optional UV0,
indexed triangles, baseColorFactor and optional canonical RGBA8 sRGB texture.
Snapshot world transforms are applied exactly; a double-precision model-view
composition avoids an unnecessary large-world float translation loss. Materials
are opaque/single-sided as validated. Metallic/roughness remain inspection data,
not a claim of PBR support. Inspector preview lighting is diagnostic and is not
Gaia runtime render parity. No IBL, normal mapping, shadow or postprocessing.

Upload each declared snapshot image once as GL_SRGB8_ALPHA8; sampler objects
preserve explicit min/mag/wrap settings independently of shared image storage.
Unspecified filters use documented LINEAR / LINEAR_MIPMAP_LINEAR preview defaults.
Mipmap storage is accounted when required. Top-to-bottom canonical rows map to
glTF UV0 without an extra vertical flip; alpha does not enable blending for an
OPAQUE material. The shader emits sRGB with framebuffer-sRGB conversion disabled,
so a texture's sRGB conversion is applied exactly once before diagnostic lighting.

The deterministic headless camera owns only target/yaw/pitch/distance/projection
parameters. It fits actual validated bounds at wide/tall aspect ratios, clamps
pitch/distance, uses positive near and ordered far planes, and ignores invalid
input deltas. Orbit/pan/zoom/frame/resize never modify model data. Grid is a finite
bounds-scaled line set, axes are reference XYZ and AABB is the actual twelve-edge
validated box. Wireframe is a draw state, not a different model interpretation.

Controls: LMB orbit; MMB or Shift+LMB pan; wheel zoom; F frame; R reload; G grid;
A axes; B bounds; W wireframe; Escape close. Input callbacks consume pressed edges,
not repeats. Focus loss clears drag/delta/key eligibility; return cannot replay
a held reload/toggle or stale mouse delta. Logical cursor and framebuffer aspect
are handled separately. There is no game input authority or UI overlay framework.

Reload is synchronous on the context owner with a single coalescing request flag:
current -> validate candidate -> complete CPU candidate -> complete GPU candidate
-> publish once -> destroy old -> update title. Failed validation/CPU/upload keeps
old geometry, snapshot and current SHA. Candidate failure SHA is separate (unknown
if admission failed before a source hash exists). Terminal reports use Gate B's
safe text writer; titles contain only fixed status and bounded hex hashes.
At most current plus candidate exist. No watcher, queue, future, async loader,
history or retry. Explicit resource counters verify steady state across 20 reloads.

Every GL create/use/delete runs on the captured context thread. Partial upload
rolls back owned handles; shutdown destroys candidate/current, helper geometry,
textures/samplers/shaders and window in reverse ownership order. No finalizers or
process-exit-as-cleanup. A small injected resource backend tests lifecycle without
mocking the complete GL API. Runtime compile/link or GL errors block acceptance.

Gate D requires fresh viewer/inspector/tools-check tests and real Windows ruler,
tool, camera/overlays/resize/focus, 20 valid reloads and invalid reload/recovery
evidence. Gate C accepted originals are read-only; replacement for reload testing
uses a dedicated ignored staging copy. Synthetic validated fixture texture tests
do not expand Gate C. Four independent read-only reviews plus a final skeptical
review follow acceptance; any verified Critical or snapshot insufficiency stops.
At most two bounded Important/Minor closure cycles. No automatic Gate E, Git
integration, Blender change or production resource admission.

## Stop conditions

### Gate 17.75B controller contract clarification — primitive attribute allowlist

V0 preserves only POSITION, NORMAL and optional TEXCOORD_0. POSITION/NORMAL are
required; textured base color requires UV0 with texCoord absent or zero. Unused
valid UV0 is allowed. All COLOR_n fail with UNSUPPORTED_VERTEX_COLOR; all other
legal attributes outside the exact allowlist fail as unsupported, malformed core
semantics as invalid glTF. No color baking or silent snapshot data loss is allowed.
The earlier vertex-color stop is resolved; budgets and rigid transforms stay frozen.

Stop for runtime dependency leakage, library licensing incompatibility,
unbounded decode behavior that cannot be excluded within this gate, need for
full semantic validation to claim admission safety, renderer/world ownership
changes, external asset requirements, or source-asset/LFS decisions. No automatic
repair of normals, transforms, scale or pivots. Unit/pivot intent and outward
normals on open surfaces require human authoring review, not invented certainty.
