# Phase 16 Gate 16C1 Implementation Notes

## Scope and frozen baseline

Gate 16C1 extends only the existing `BlockRaycast` world DDA with typed DETAIL parent refinement. Gate 16A's sparse canonical representation and Gate 16B's mutation, revision, dirty, and persistence contracts remain unchanged. No collision, meshing, save-codec, or debug-tool behavior is introduced by this gate.

## Authority and observation

- `BlockRaycast` remains the only world-level DDA authority.
- Every visited parent is observed through `World.observeCell`, which delegates to the repository-owned typed `ParentCellObservationResult` seam.
- FULL observations use the existing `BlockCollisionShapeResolver` path.
- DETAIL observations use the immutable `DetailCellState` carried by the observation and never reinterpret the backing FULL AIR byte.
- Origin-aware casts preserve `AVAILABLE`, `UNKNOWN`, and `FAILED`. The legacy Optional cast fails closed with `IllegalStateException` when canonical space is unavailable rather than returning a false miss.
- Raycast performs no repository mutation, revision allocation, dirty tracking, worker publication, or GPU work.

## DETAIL refinement and deterministic ties

The refiner iterates the immutable 64-bit occupancy mask in ascending deterministic subvoxel index order. Indexing is X-fast (`x | y << 2 | z << 4`). Each occupied cell is intersected as exact primitive quarter-grid bounds. It reuses the FULL slab comparison, entry-face priority, and candidate tie ordering. Empty parent-space along the ray returns no parent candidate, so the same outer DDA continues to later parents.

The fixed bound is 64 occupancy tests per DETAIL parent. The loop allocates no copied material array and no AABB object per tested subvoxel. A `Candidate` is created only for an actual bounded slab intersection, and `LocalSubVoxelPosition` / `DetailRaycastTarget` are created only for the selected hit.

## Hit provenance and game integration

`BlockRaycastHit` and `BlockHitResult` now carry:

- canonical parent coordinate;
- exact local `DetailRaycastTarget` position and `VoxelScale.DETAIL_4`, or the FULL singleton discriminator;
- face normal and adjacent parent coordinate;
- resident-local float point and canonical double world point;
- normalized ray distance;
- runtime block ID in engine and registry-resolved `ResourceLocation` in game;
- exact observed owning Chunk revision.

DETAIL hits require a positive observed Chunk revision. Existing 14-argument constructors remain as FULL-only compatibility seams and produce the FULL discriminator with revision zero.

`GaiaBlockRaycastService` remains an identity adapter and maps the exact runtime ID through `BlockRegistry`. `BlockInteractionController` exposes DETAIL targeting but explicitly leaves it non-mutating: primary/secondary input returns `gaia:interaction/detail_target_unsupported` rather than issuing a legacy parent FULL mutation. Gate 16B still revalidates any later detail mutation request; the hit grants no mutation authority.

## TDD evidence

The production changes were preceded by these observed RED states:

1. A DETAIL parent whose backing FULL byte was AIR threw from the legacy raw-byte seam instead of hitting canonical DETAIL geometry.
2. The complete engine behavior fixture ran against the pre-refinement seam: 11 tests ran and all 11 failed, covering single/nearest hits, gaps to later FULL/DETAIL, six faces, edge/corner ties, origin-inside/surface, negative and Chunk-boundary coordinates, nonzero/rebased origins, unavailable continuation, and distance bounds.
3. Provenance tests produced 27 compile errors before the target discriminator, canonical point, and revision fields existed.
4. Game mapping/integration tests produced 18 compile errors before game hit provenance and explicit DETAIL interaction safety existed.
5. The checked immutable material accessor test produced 5 compile errors before `DetailCellState.blockIdAtIndex` existed.
6. Two provenance-constructor tests failed because zero-revision DETAIL hits were accepted; both passed after validation was added.
7. The legacy fail-closed test failed because UNKNOWN returned `Optional.empty`; it passed after unavailable space became explicit failure in that compatibility seam.

Two initial GREEN fixture failures were diagnosed as test setup errors: their rays entered unloaded neighboring chunks before reaching the intended geometry. The fixtures now explicitly load every traversed Chunk; no production UNKNOWN rule was weakened.
