# Phase 16 Gate 16C2 Implementation Notes

## Scope and frozen baseline

Gate 16C2 extends only the existing `CollisionWorld` static-voxel shape-resolution seam with typed DETAIL collision. Gates 16A, 16B, and 16C1 remain frozen. This gate does not add meshing/render work, debug tooling, gameplay material economy, a collision cache, worker ownership, or a second physics authority.

## Collision authority and typed observation

- `CollisionWorld` remains the sole broad-phase, sweep, move-and-slide, overlap, and depenetration authority.
- Every queried parent now uses `World.observeCell` and `ParentCellObservationResult` rather than inferring canonical geometry from the legacy FULL backing byte.
- AVAILABLE FULL observations retain the existing `BlockCollisionShapeResolver.shapeFor(byte)` behavior, including custom/multi-AABB FULL shapes.
- AVAILABLE DETAIL observations pass immutable `DetailCellState` occupancy to the narrow `DetailCollisionBoxMerger` helper. Runtime material IDs do not split otherwise continuous solid collision volume.
- Origin-aware UNKNOWN and FAILED observations keep the existing typed unavailable-space result. The legacy non-origin-aware compatibility methods retain their pre-existing AIR-resolver fallback for unavailable Chunks.
- Collision observation performs no canonical mutation, revision allocation, dirty tracking, caching, worker publication, GPU work, or game-layer lookup.

## Deterministic DETAIL shape

For one DETAIL parent, the merger copies only the immutable 64-bit occupancy mask into a local `remaining` value. It repeatedly chooses the lowest X-fast index (`x + 4*y + 16*z`), then expands continuously occupied cells in the fixed order +X, complete +Y rows, complete +Z layers. The merged volume is cleared from `remaining`, emitted once, and processing continues in ascending seed order.

All bounds are integer quarter coordinates converted directly to `float`: `0`, `0.25`, `0.5`, `0.75`, and `1`. No accumulated stepping or tolerance inflation is used. Tests reconstruct every one of the 64 cells from box-center coverage and prove that every occupied cell is covered exactly once while every empty cell is uncovered. A full DETAIL cube becomes one full-parent AABB; checkerboard fragmentation produces 32 boxes. For any canonical non-empty state, box count is between 1 and the occupied-cell count and therefore never exceeds the absolute 64-cell bound. Materials are deliberately ignored for collision merging because Phase 16 v1 occupancy is the DETAIL solid-geometry authority.

## Allocation and lifecycle bound

FULL-only queries do not create DETAIL state or invoke the DETAIL merger; they keep the existing resolver path. Each queried DETAIL parent creates one bounded `ArrayList` sized to its occupied-cell count, one to 64 immutable `Aabb` values, the immutable list copy owned by `BlockCollisionShape`, and one `BlockCollisionShape`. There is no allocation proportional to world distance beyond the already bounded parent broad-phase, no rigid body per subvoxel, no global collection, and no persistent cache. Complexity is bounded by queried parent cells multiplied by at most 64 boxes.

## TDD evidence

The production changes were preceded by these observed RED states:

1. The first DETAIL collision fixture reached legacy `World.getBlock`; all 11 initial integration tests failed with `IllegalStateException` because raw bytes cannot represent a DETAIL parent. This directly proved the backing-AIR bypass.
2. `DetailCollisionBoxMergerTest` failed compilation with two missing-type errors before the deterministic quarter-grid resolver existed.
3. The typed FULL/DETAIL resolver contract failed compilation with two missing-method errors before `BlockCollisionShapeResolver` exposed its typed default seam.
4. After the minimal typed integration, 17 of 18 target tests passed. The remaining player-step failure was traced to a bounded fixture whose short platform allowed the player to walk off before assertion. Extending the fixture preserved production physics and produced GREEN; no collision epsilon, speed, or step behavior was changed.

Adjacent hardening then covered exact contact, fixed-step maximum configured movement, direct and diagonal quarter-wall sweeps, simultaneous vertical/horizontal contact, DETAIL inside corners, multiple greedy boxes, parent-spanning DETAIL/DETAIL and DETAIL/FULL depenetration, stable quarter/half/three-quarter/full grounding, quarter-grid stairs, Chunk and negative-Chunk seams, UNKNOWN/FAILED barriers, SimulationOrigin rebase equivalence, restore visibility, final-clear disappearance, and uniform compaction back to FULL semantics.
