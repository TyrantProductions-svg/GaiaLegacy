# Phase 17 Gate 17B Implementation Notes

Date: 2026-08-30
Scope: atomic parent mutations and Creative DETAIL editing only
Status: implementation complete; Gate 17C has not begun

## Frozen authorities

- `ChunkRepository` remains the only canonical voxel, revision, dirty, and invalidation authority.
- `GaiaDetailMutationService` remains a game-layer material translation and owner-thread adapter.
- `BlockInteractionController` remains the sole fixed-step gameplay interaction owner.
- Gate 17B adds no raycaster, collision authority, mesh scheduler, inventory economy, or WorldItem recovery path.
- The Phase 16 mesh limits and scheduler/GPU budgets are unchanged.

## Task 8 - Atomic RemoveDetailParent

RED: `ChunkDetailParentRemovalTest` demonstrated that the engine API could not express an exact-state whole-parent DETAIL removal.
GREEN: added `RemoveDetailParentRequest`, the corresponding `DetailMutationService` operation, a sealed `ChunkDetailMutation.RemoveDetailParent` command, and one repository CAS branch.

The applied transition is exactly `DETAIL -> FULL AIR`. It validates the positive expected Chunk revision and exact immutable DETAIL state, publishes one revision, produces one dirty/invalidation outcome, and never loops over 64 cells. Stale revision or state mismatch leaves state and revision unchanged. Existing boundary invalidation supplies face, edge, corner, cross-Chunk, and negative-coordinate behavior.

## Task 9 - Atomic SculptParentSubVoxel

RED: `ChunkDetailSculptTest` demonstrated that FULL sculpt and first-cell placement could not publish their final representation in one repository mutation.
GREEN: added `SculptParentSubVoxelRequest`, the corresponding service operation and sealed command, plus one repository CAS branch.

Covered final transitions:

- non-AIR FULL removal -> 63-cell DETAIL in one revision;
- FULL AIR placement -> one-cell DETAIL;
- DETAIL removal, placement, and material replacement -> final DETAIL state;
- last occupied DETAIL removal -> FULL AIR;
- 64/64 uniform DETAIL remains DETAIL.

No intermediate uniform DETAIL revision is observable. Empty DETAIL is never stored.

## Task 10 - Gaia mutation translation

RED/GREEN coverage in `GaiaDetailMutationServiceTest` proves the adapter translates canonical `ResourceLocation` material identity to the existing runtime byte and delegates both atomic operations under the existing simulation-owner guard. Explicit `Optional.of(gaia:air)` replacement is rejected as `UNKNOWN_MATERIAL`; only `Optional.empty()` means removal, avoiding an alias between material replacement and deletion.

## Task 11 - Creative precision transaction and overlap

RED: `CreativeDetailEditTransactionTest` covered stale observation, exact FULL/DETAIL sculpt, valid placement, occupied/unavailable rejection, player overlap, and no economy side effects.
GREEN: `CreativeDetailEditTransaction` re-observes canonical state, submits exactly one CAS operation, and returns a bounded `DetailEditResult` without retrying or retargeting.

`DetailPlacementCollisionValidator` consumes the accepted quarter AABB and converts canonical-global coordinates through the current `SimulationOrigin` before comparing it with the resident-local player body. Tests cover partial/full overlap, deterministic boundary touch, cross-parent placement, and rebase.

## Task 12 - Creative coarse whole-parent transaction

RED/GREEN coverage in `DetailParentBreakTransactionTest` proves the coarse route submits exactly one whole-parent removal and creates no micro drop, full-block drop, inventory mutation, or WorldItem. Feedback is eligible only after `APPLIED`.

## Task 13 - Sole-controller dispatch and feedback

RED: `BlockInteractionControllerDetailCreativeTest` showed accepted Gate 17A routes were read-only.
GREEN: `BlockInteractionController` dispatches Creative coarse remove, precision FULL/DETAIL remove, and precision placement from one route decision and one canonical target observation. Survival detail routes return the explicit deferred result and do not mutate for free.

`CommittedGameplayFeedback`, `InteractionFeedbackCoordinator`, and `GameplayParticleFeedback` provide bounded APPLIED-only detail debris. Particle positions are converted through the current `SimulationOrigin`; rejected, stale, overlap, and unavailable actions produce no committed feedback. The preview remains immutable and is cleared after committed state change.

## Atomicity and propagation evidence

- Repository tests assert one revision and exact expected-state CAS behavior.
- Existing repository invalidation covers interior, parent boundary, Chunk boundary/corner, and negative coordinates.
- No game transaction edits `DetailStorage`, Chunk dirty state, mesh state, collision state, or GPU state directly.
- Existing `detail-blocks` persistence, snapshots, raycast, collision, and mesh composition consume the resulting canonical revision.
- Creative inventory snapshots and WorldItem state remain unchanged by design and tests.

## Runtime smoke

Real Windows GLFW/OpenGL runtime, development-provisioned Creative chisel:

- precision FULL sculpt changed one FULL grass parent to 63-cell DETAIL in one action;
- precision DETAIL removal changed only the targeted occupied quarter;
- precision placement inserted the selected dirt quarter;
- placement against FULL AIR created a one-cell DETAIL parent;
- a fresh process reloaded the saved sculpted/placed geometry successfully;
- with the ordinary Creative held block (no debug chisel provisioning), primary interaction removed one targeted DETAIL parent as a single coarse action;
- repeated invalid/overlap-oriented placement attempts caused no revision change or crash;
- the modified pattern completed Save & Quit and the first process exited cleanly.

Automated tests provide exact cross-parent/cross-Chunk and overlap assertions. Cross-parent placement was not independently isolated by camera positioning in the first interactive run. Resize remains a Gate 17D manual acceptance item. Native Apple Silicon runtime was not run.
