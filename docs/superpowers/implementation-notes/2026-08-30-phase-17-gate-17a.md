# Phase 17 Gate 17A implementation notes

Date: 2026-08-30
Branch: `feat/small-voxel-tools`
Baseline: `4e45a6681f169e070500e4580c62fb37dc53d4ed`

## Scope and status

Gate 17A implements read-only canonical item identity, interaction routing,
precision targeting, placement preview, input lifecycle, and ghost presentation.
It deliberately performs no world, inventory, WorldItem, dirty-state, revision,
save, or mesh mutation. Gate 17B atomic edit operations are not present.

## Task evidence

### Task 1 — standalone item domain and one item-form index

- RED: focused registry tests failed because standalone item definitions,
  capability identity, and presentation identity did not exist.
- GREEN: `BlockRegistry` now owns block-backed and standalone item forms in the
  same canonical item slot. `blockForItem()` remains the strict block-only API.
- Added `ItemCapability`, `ItemVisualType`, `ItemVisualReference`, and
  `StandaloneItemDefinition`.

### Task 2 — strict resources and canonical v1 items

- RED: production resource tests could not load a standalone item list or the
  three required identities.
- GREEN: `GaiaResourceLoader` strictly loads the optional canonical `items`
  list and validates the standalone item documents.
- Added `gaia:chisel`, `gaia:stone_detail_unit`, and
  `gaia:dirt_detail_unit`. Chisel is max-stack 1, one-handed, not
  mouth-holdable, and has `DETAIL_PRECISION`; units are max-stack 64.

### Task 3 — standalone visual resolution

- RED: existing presentation required `blockForItem()` and rejected a chisel.
- GREEN: visual resolvers first consume explicit standalone `ATLAS_REGION`
  presentation and preserve the existing block-backed path as fallback.
- Identity, capability, and presentation remain separate. The presentation
  seam can later name another visual type without changing ItemStack identity.

### Task 4 — pure canonical route resolver

- RED: DETAIL targets could only reach legacy unsupported behavior.
- GREEN: `CanonicalBlockInteractionRouteResolver` returns typed routes for
  FULL normal interaction, DETAIL coarse removal, precision removal,
  precision placement, rejection, and unavailable observations.
- The resolver is pure and owns no input, repository, raycast, or mutation
  authority.

### Task 5 — FULL face-local quarter refinement

- RED: a FULL hit had no deterministic quarter coordinate suitable for a
  precision preview.
- GREEN: `DetailTargeting` performs bounded face-local quarter refinement for
  all six faces using the Phase 16 quarter/tie conventions.
- Boundary, negative-coordinate, and origin-rebase cases are covered.

### Task 6 — DETAIL placement candidates

- RED: DETAIL face placement could not wrap into an adjacent parent or observe
  the destination through typed canonical state.
- GREEN: `DetailTargeting.placementCandidate()` wraps the local coordinate and
  parent coordinate, including Chunk boundaries and negatives, then consumes
  `DetailTargetWorldView` typed AVAILABLE/UNKNOWN/FAILED observations.
- Empty DETAIL gaps remain BlockRaycast pass-through space; no synthetic target
  or second traversal was added.

### Task 7 — preview, input lifecycle, and ghost

- RED: immutable preview state, material cycling, controller projection, and a
  presentation adapter were absent.
- GREEN: one immutable `DetailPlacementPreview` is owned by a bounded
  `DetailPreviewController`. The existing `BlockInteractionController` remains
  the sole fixed-step owner and publishes read-only route/preview state.
- Primary selects precision-remove, secondary selects precision-place,
  Shift-secondary retains pickup precedence, and `R` cycles only stone/dirt
  while a precision-capable item is active. Focus/menu/session invalidation
  clears current preview state.
- `DetailPlacementGhostAdapter` appends at most one transient preview through
  the existing feedback frame. It never enters snapshots, collision, raycast,
  saving, inventory, or the mesh lifecycle.

## Item and resource architecture

The existing `BlockRegistry` remains the single canonical owner of item-form
identity. Standalone item definitions coexist with block-backed forms; there is
no `ItemRegistry`, tool registry, or detail-unit registry. ItemStack remains a
`ResourceLocation` plus integer count with no metadata.

The temporary chisel visual is a project-owned 16x16 atlas-region silhouette
with a dark handle and light steel tip. Detail units explicitly reference the
existing stone and dirt block atlas regions. The UI icon atlas contains the
same chisel silhouette, while detail-unit UI presentation uses explicit
stone/dirt aliases rather than inferring gameplay material from coordinates.

## Runtime-only UI icon correction

The first Windows smoke found a bounded `[UI] Missing icon for gaia:chisel`
diagnostic. The world/held atlas path was correct; the independent HUD icon
atlas lacked the standalone chisel identity. A focused RED demonstrated the
absence of an explicit standalone alias seam. The minimal GREEN added:

- one chisel cell in the existing UI icon atlas;
- explicit immutable detail-unit-to-stone/dirt UI aliases;
- production asset validation for the chisel icon.

The correction does not infer gameplay identity from visual data and does not
create another item authority.

## Independent-review corrections

The first review found three Important issues and one Minor guard gap. Each
behavioral issue received a focused RED before its minimal correction:

- quarter ghosts now translate from the quarter AABB center relative to the
  parent-cell center used by `TransientBlockVisualPass`;
- production forwards `pickupPressed` into the sole controller, pickup
  consumption reaches the canonical resolver before AVAILABLE/UNKNOWN/FAILED
  target handling, and route-driven edge dispatch cannot publish a placement
  action for pickup input;
- strict item loading rejects standalone visual atlases that the v1 runtime
  presentation path does not upload;
- architecture guards now reject concrete and interface-typed repository,
  world, mutation, inventory, WorldItem, collision, mesh, raycast, and target
  authorities on preview/target/ghost surfaces.

The final independent re-review reported 0 Critical, 0 Important, and 0 Minor.

## Runtime smoke

Windows real GLFW/OpenGL smoke used the development inventory-shortcut flag and
an existing accepted world:

- Creative selection resolved `gaia:chisel` and showed its held/HUD visual;
- FULL and DETAIL targeting produced one quarter ghost; the post-review smoke
  showed the corrected dirt preview contained within the selected stair
  quarter rather than translated outside the parent;
- `R` changed the selected preview material between stone and dirt;
- precision primary/secondary produced no world mutation, as required for 17A;
- focus loss paused input and focus return recreated current target state;
- Q/Ctrl+Q showed no precision-path regression;
- the post-fix terminal emitted no missing-chisel-icon diagnostic.

Window resize was attempted but not independently confirmed because captured
cursor input and Windows DWM ownership prevented a reliable target-window
resize. A follow-up Computer Use smoke exited through the game's own
`Quit -> Confirm` path; the Gaia window closed and `:game:run` returned exit 0.
The resize item remains an acceptance limitation, not an automated behavior
claim.

## Known limitations and deferred work

- Gate 17A is intentionally read-only; atomic parent/subvoxel mutation begins
  only after Gate 17B authorization.
- No survival acquisition, crafting, recovery, units conversion, durability,
  tool tier, harvest tier, progression, GLB/model loader, or natural DETAIL
  generation exists.
- The `R` binding remains a provisional Phase 17 policy and showed no conflict
  in repository input scans or focused input tests.
- Native Apple Silicon interactive runtime was not part of this Gate.
