### C1 — palette-PNG ancillary metadata exceeds the allocation boundary

`EmbeddedImages.java:51,62,71` passes `ignoreMetadata=true` but retains pending
readers until all pixel decoding completes. `pngContainer` checks encoded bounds
and CRCs, not ancillary-chunk count/retained metadata. Installed JDK21
`PNGImageReader.java:718` excludes palette images from its metadata-skipping branch;
lines 882-900 allocate and retain data/name objects for unknown ancillary chunks.
The RGBA budget counts only width * height * 4, not those objects. Repeated image
declarations may reference the same view and cause independent retention.

Reviewer bounded JDK-reader probe: a project-generated 1x1 indexed PNG with 10,000
CRC-valid `raNd` chunks occupied 120,847 encoded bytes and decoded successfully
with `ignoreMetadata=true`; its metadata retained exactly 10,000 UnknownChunks.
The production chain and installed JDK source corroborate the allocation path.
Near the admitted file cap, chunk-object amplification can threaten the 256 MiB
tool heap despite tiny pixel dimensions. No large/OOM attack was run. The attempted
full-validator probe did not complete due to class-loading failure; no whole-path
PASS/OOM reproduction is claimed.

Minimal proposed closure, NOT implemented: establish a pre-reader metadata/chunk
allocation bound accounting for repeated images, or use a demonstrated
metadata-independent decoding boundary. This Critical requires controller direction;
do not silently add a new acceptance restriction or dependency.

### I1 — nondefault scene roots are not checked for parentlessness

`SceneChecks.java:46-48` checks root indices in other scene declarations, but not
whether those nodes are children. Default scene root 0 -> child 1 plus secondary
scene roots [1] can traverse the default scene successfully. Core glTF requires
every scene.nodes entry to be a root, not any node's child. This is source-verified;
no main-agent runtime reproduction was claimed. Proposed closure: validate all
declared scene roots against the bounded parent map, retaining default-only
expanded accounting.

### I2 — decoded texture colors are changed before snapshot publication

`EmbeddedImages.java:62-68` uses reader.read followed by BufferedImage.getRGB.
JDK JPEGImageReader applies ICC conversion even with ignoreMetadata=true
(`checkColorConversion`, installed source lines 1079-1084). Reviewer decoder-only
in-memory probe kept JPEG compressed pixels identical: adding a linear-RGB ICC
profile changed pixel ff3f607f to ff88a5bb. A grayscale PNG raw sample 64 became
137/137/137 through getRGB. These are bounded decoder-level results, not successful
full-validator probes. The production path retains the converted RGBA without
restoration. glTF requires image colorspace metadata to be ignored. Proposed
closure: metadata-independent, sample-faithful RGBA extraction and permanent
full-validator ICC/grayscale controls, without changing the frozen profile.

### I3 — text diagnostics permit terminal-control injection

`ValidationReportWriter.java:35` appends untrusted attribute paths literally.
Reviewer full-validator/writer reproduction used an attribute containing LF, CR
and ESC[2J: the text report included those controls, allowing report spoofing or
terminal clearing. JSON escaped them safely; validation still FAILed with no
snapshot. Proposed closure: visibly escape text-control characters at the output
adapter, preserve semantic identity/ordinary Unicode, and add an end-to-end test.

### M1 — valid custom attribute syntax receives the wrong failure category

`GeometryChecks.java:59` restricts custom names to `_[A-Za-z0-9_]+`; core glTF
requires an underscore prefix, not this ASCII-only suffix. Names such as
`_UV.custom` or `_温度` should remain unsupported profile attributes, not invalid
core syntax. Both currently FAIL/no snapshot. Proposed closure: correct only the
classification and retain the exact v0 allowlist.

### M2 — truncated paths silently collapse diagnostic identities

`ValidationReport.java:16,44` bounds paths before TreeSet identity comparison.
Reviewer full-path probe with 100 unsupported attributes sharing a 200-character
prefix produced one diagnostic with truncated=false; short-name control produced
64 diagnostics with truncated=true. FAIL/no snapshot remains correct. Proposed
closure: make lost diagnostic/path information observable in truncation state and
add a shared-prefix regression without unbounded retained strings/history.

Core specification references used to verify scene-root, custom-semantic and
image-color requirements: [Khronos glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).
