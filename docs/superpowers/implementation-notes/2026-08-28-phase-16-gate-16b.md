## Frozen Gate 16A representation

- Sparse DETAIL membership remains the physical discriminator.
- Every stored DETAIL entry has `occupancyMask != 0`; every clear material slot is runtime ID `0`.
- A DETAIL parent's backing FULL byte is AIR `0`.
- Absence of a DETAIL entry is FULL, including FULL AIR.
- The shared empty `DetailChunkSnapshot` is a non-owning view only. It is never stored, serialized, revision-authorized, meshed, raycast, or collision-authorized as DETAIL.
- FULL-only Chunks retain `detailStorage == null` and allocate no DETAIL arrays.
- The per-Chunk hard cap remains 1,024 DETAIL parents and world height remains at most 256.

## Canonical mutation transaction

`ChunkRepository.mutateDetail` is the only canonical commit point. Request validation and revalidation occur under the existing entry lock and use the current Chunk revision plus exact expected typed parent/subvoxel state.

- FULL non-AIR to DETAIL installs one uniform 64-cell `DetailCellState`, clears the backing FULL byte, and allocates exactly one canonical repository revision.
- FULL AIR to the first occupied subvoxel installs one nonempty sparse entry atomically.
- DETAIL edits use exact expected occupancy/material state.
- Clearing the final occupied subvoxel removes sparse membership and produces FULL AIR atomically.
- Explicit uniform DETAIL-to-FULL compaction is supported only after exact compatibility validation; no opportunistic compaction occurs.
- Rejections allocate no revision, create no dirty state, invalidate no neighbors, and have no persistence side effect.
- Successful mutations use existing `voxelModified`, dirty revision, active-unload invalidation, and `ChunkDirtyTracker.affectedByBlock` authority. No DETAIL revision or dirty tracker exists.

`GaiaDetailMutationService` translates `ResourceLocation` requests through the existing `BlockRegistry`, preserves actor/tick context, and delegates the actual CAS/revision/dirty commit to `ChunkRepository`.

## Exact streamed codec v1

Descriptor:

```text
sectionId = detail-blocks
codecVersion = 1
required = true
```

Payload is big-endian:

```text
4 bytes  magic GLD1
1 byte   scale = 4
1 byte   flags = 0
2 bytes  paletteCount, 1..255
4 bytes  parentCount, 1..1024

paletteCount times:
  2 bytes UTF-8 byte length, 1..128
  N bytes strictly ascending canonical ResourceLocation text

parentCount times, strictly ascending unsigned parent index:
  2 bytes parent index
  8 bytes occupancy mask, nonzero
 64 bytes one-based palette codes; zero only for unoccupied cells
```

The palette contains no AIR, duplicates, unknown names, or fallback IDs. Runtime byte IDs are translated to canonical game `ResourceLocation` names on encode and back through the current `BlockRegistry` on decode. Engine storage contains no game-layer identity objects.

The exact worst case is exercised through the production encoder:

```text
header                         12
255 * (2 + 128) palette    33,150
1,024 * (2 + 8 + 64)      75,776
total                       108,938 bytes
```

This remains below the existing 1 MiB extension limit. No Phase 15 bound changed.

Absent `detail-blocks` is valid FULL-only state. Present v1 with `required=false`, malformed bytes, unknown material, invalid occupancy/code agreement, backing conflict, duplicate/out-of-range parent, count 1,025, or trailing bytes fails closed without exposing partial `ChunkGenerationData`. Reserved DETAIL bytes are retained by outer framing for semantic rejection rather than skipped as an unknown optional extension.

## Exact persistence capture and no-op equality

`ChunkDetailPersistence` derives canonical FULL backing bytes and the deterministic DETAIL extension from the same immutable `ChunkSnapshot` that supplies key, revision, height, and ordered DETAIL state. No later live Chunk callback supplies DETAIL bytes.

- Mutation after capture cannot contaminate the prepared payload.
- Save-target merge replaces only `detail-blocks` and preserves unrelated extension descriptors and bytes.
- Persistence equality compares canonical FULL bytes plus canonical DETAIL descriptor bytes.
- A DETAIL-only difference cannot take the flat-byte no-op path.
- A byte-identical FULL+DETAIL no-op is legal only when the resident revision already equals the durable revision; it returns no unwritten `persistedChunkRevision`.
- A higher modified revision with identical FULL+DETAIL content is physically published before that exact revision is acknowledged. Returning to generated FULL-only state removes the obsolete payload through a real root transaction without claiming a Chunk revision.
- Modified unload replaces only capture-owned `detail-blocks`, preserves durable non-DETAIL descriptors byte-for-byte, and fails closed without publication if a capture attempts to replace an independently owned descriptor.
- Store CAS, exact ticket/revision freshness, and owner reconciliation remain unchanged.

Production save composition injects the existing game `BlockRegistry`. Owner-prepared unload capture uses the same snapshot translator. A present DETAIL extension counts as voxel-modified relative to FULL-only world generation even when flat FULL bytes equal the generated base.

## Restore and backward compatibility

`StreamedChunkCanonicalDecoder` is the single semantic streamed-payload decoder for bootstrap restore and detached streaming load.

- Extension absent: reconstruct existing FULL-only `ChunkGenerationData` unchanged.
- Supported v1 present: validate and reconstruct immutable `DetailChunkSnapshot` plus canonical FULL backing.
- Unsupported or malformed present: return a closed failure with diagnostic and no Chunk data.
- Owner publication continues through existing `ChunkGenerationData`/repository lifecycle; workers decode detached immutable bytes only.

Covered compatibility includes Phase 14 migrated FULL-only payloads, Phase 15 streamed payloads without DETAIL, ordinary FULL-only save/load, and existing streamed framing versions. Old Chunks are not rewritten merely because Gate 16B understands DETAIL.
