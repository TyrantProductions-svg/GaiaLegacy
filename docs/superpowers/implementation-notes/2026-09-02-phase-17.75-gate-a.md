## Actual JglTF reader limitation

The first adapter called `GltfAssetReader.readWithoutReferences` with a throwing
JSON error consumer. Input `buffers: "PRIVATE_MARKER"` still returned an asset and
printed that marker through JglTF's logging consumer. The six-test run had one
failure, at `decoderRejectionDoesNotEchoInputOrRetainAnUntrustedException`.

Inspection of pinned `GltfReader` / `JacksonUtils` shows constructor-time mapper
configuration captures the original logging consumer in property wrappers;
subsequent registration of the same module does not replace it. We did not
weaken the assertion, intercept global logging, use reflection, patch JglTF or
add a full schema validator. The adapter now performs strict Jackson binding
to public v2 DTOs and `GltfAssetV2`, after preflight. It fails closed on binding
errors and retains no source-bearing exception. Reader acceptance is limited:
the tolerant reader is NOT admitted for production untrusted input.

The trusted fixture test may use the upstream reader and `GltfModels.create` on
its own in-memory triangle. Production never expands an arbitrary model. A
successful admission receipt has explicit scope `PREFLIGHT_AND_ASSET_MAPPING_ONLY`.

## Strict scalar mapping closure — controller-authorized follow-up

The subsequent four-reviewer independent audit returned **0 Critical / 1 Important /
0 Minor** after deduplication. The original 53 passing tests did not cover lossy
scalar coercion: disabling `ALLOW_COERCION_OF_SCALARS` alone still allowed fractional
integer fields and numeric/boolean string fields to receive admission receipts.
This was a Gate A mapping defect, not deferred Gate B semantic validation.

Only `GlbAdmission.java`, `GlbAdmissionTest.java`, these notes and the handoff are
changed by this closure. The frozen design/contract, preflight, dependency graph,
licenses, fixtures and engine/game source are unchanged.

The centralized mapper additionally disables `ACCEPT_FLOAT_AS_INT` and sets
Textual coercion from Integer, Float and Boolean to `Fail`. No per-field validator,
nullability policy, geometry/material/image validation or alternate decoder was
added. Integer JSON tokens remain usable for legitimate floating numeric targets.

## Gate E controller contract closure — strict array nulls

Gate E's final security review later found that Jackson 2.22.1 could map a null
element in a primitive `double[]` to zero even though scalar coercion and packed
string paths were already strict. Five full-admission RED cases reproduced this
for translation, rotation, scale, matrix and baseColorFactor. Core boxed index-list
nulls were already rejected by the existing DTO binding path.

The centralized mapper now enables `FAIL_ON_NULL_FOR_PRIMITIVES`; no Gate B
per-field repair or raw-JSON replay was added. Full-admission positive controls
retain authored zeroes, integer lexical values for numeric double targets, optional
whole-property nulls and bounded `extras` null values. Initial direct GREEN after
the correction was 324/324; final closure totals are recorded in Gate E notes.
